## ПРОМТ (можно вставлять целиком в любую модель)

```
Ты — Senior Software Architect и Full-Stack разработчик.
Добавляешь в СУЩЕСТВУЮЩЕЕ приложение Electric Pro (V29) новый модуль
"Проект квартиры" — визуальный план электрики. Встраивается как пункт
бургер-меню, БЕЗ отдельной сборки и без смены стека.

=== ЦЕЛЬ ===
Мобильный инструмент проектирования электрики для работы на объекте
(телефон и планшет, пальцем). Три задачи одновременно:
- расчёт и смета (материалы, кабель, штробы, подрозетники);
- документ для клиента (наглядный план, легенда, PDF);
- рабочая карта себе (куда что ставить, высоты, трассы, прогресс монтажа).

=== СТЕК (СТРОГО как в текущем проекте) ===
- Чистый JavaScript (ES2020), без сборщика, без TypeScript, без React.
- Модули — IIFE, регистрируются в глобальном namespace EP.*.
- Графика — SVG (образец: assets/js/modules/shield/shield-scheme-svg-v28.js).
- Состояние — JS-объект + localStorage; облако поверх через EP.Cloud.
- Роутинг — маршрут в EP.routes + pages/plan.html + пункт бургер-меню +
  <script defer> в index.html.
- Только русский; строки в одном месте (задел под i18n), библиотеку НЕ ставить.

=== ПРАВИЛА ПРОЕКТА ===
- Файлы не больше 300–500 строк; дробить.
- Без дублирования, костылей, магических чисел, техдолга.
- Все настраиваемые параметры — в одном центральном конфиге DEFAULTS
  (как в pool-engine-v29), редактируются пользователем.
- Защищённые зоны (БД, конфигуратор щита, пул, схема) НЕ трогать —
  только переиспользовать их публичные API.
- Офлайн-first: всё работает без сети, облако — best-effort поверх.

=== ИНТЕГРАЦИЯ (реальные API, НЕ выдумывать) ===
1) Маршрут: в assets/js/core/router.js добавить в EP.routes:
     plan: "pages/plan.html"
   Создать pages/plan.html:
     <section class="page"><div id="ep-plan-root"></div></section>
   Роутер сам грузит HTML в #pageContent и шлёт событие "ep:route-loaded"
   (e.detail.route === "plan").
2) Бургер-меню: в assets/js/core/app-shell.js в список .side-menu:
     <button class="ep-clickable" type="button" data-route="plan">🏗️ Проект квартиры</button>
3) Монтаж модуля:
     window.addEventListener("ep:route-loaded", (e) => {
       if (e.detail && e.detail.route === "plan") { /* render в #ep-plan-root */ }
     });
4) База материалов/работ — EP.Database:
     EP.Database.getItemsByType("material"|"work"), .getItems(),
     .categories(type), .subcategories(type, category)
     Позиция: { id, name, type, unit, price, category, subcategory }
5) Расчёт (ПЕРЕИСПОЛЬЗОВАТЬ) — EP.PoolEngine:
     const res = EP.PoolEngine.calc({ blocks:[{material, route:"ceiling"|"floor",
       height, sockets, sw1, sw2, sw3, pass, cross, tv, internet, warmFloor}],
       ceilingHeight:270, mode:"junction"|"boxes" });
     res.draftItems -> [{type, name, qty, unit}]  // готово в смету
     res.cable, res.junctions, res.byMat — доп. данные;
     EP.PoolEngine.DEFAULTS — дефолты/нормативы.
6) Смета — EP.Estimate:
     EP.Estimate.addItem({name, price, qty, type, unit}); .total(); .getItems(); .clear();
7) Облако — EP.Cloud:
     EP.Cloud.push("plan", data); EP.Cloud.pull("plan"); EP.Cloud.onLogin(fn);
8) ИИ (для проверок) — EP.AI: EP.AI.ask(messages) уже существует.
9) Экранирование HTML — локальная esc() с кавычками.

=== ГЛАВНЫЙ ПРИНЦИП: ОДНА МОДЕЛЬ — МНОГО ВИДОВ ===
План, развёртка стены, список материалов, PDF, 3D — это разные проекции
ОДНИХ данных. Элемент привязан к стене: { стена, отступ_от_угла(см),
высота_от_пола(см) }. План рисует его на линии стены, развёртка — на
плоской стене. Двусторонняя синхронизация получается сама, писать её не надо.

=== МОДЕЛЬ ДАННЫХ ===
Project { id, name, address, clientId?, settings, underlay?, rooms[],
          panels[], elements[], routes[], layers[], versions[], updatedAt }
Underlay { imageDataUri, scale /*см на пиксель*/, opacity }
Room    { id, name, points:[{x,y}...] /*полигон; прямоуг.=4 точки*/,
          height /*потолок*/, zones:["wet"?] }
// Стена — производная от рёбер комнаты: id = roomId+индексРебра, номер,
// толщина; a,b,длина,направление вычисляются из точек.
Panel   { id, x, y, name }
Element { id, type, wallId, offset /*см*/, height /*см*/, layer,
          status:"planned"|"mounted"|"existing", circuitId?, photos:[dataURI],
          params }
  type: socket|switch|light|ac|warmfloor|internet|tv|camera|sensor|panel
Route   { id, layer, routeType:"ceiling"|"floor"|"wall", points:[{x,y}],
          fromId, toId, throughWalls:[...] }
Layer   { id, name, visible, opacity, color }
  слои: освещение, силовые, слаботочка, ТВ, видеонаблюдение, кондиционеры,
        тёплый пол, трассы, размеры, подписи
Circuit { id, name, elements:[id], breaker?, rcd? } // группа/линия

=== СТРУКТУРА МОДУЛЯ (мелкие файлы) ===
assets/js/modules/plan/
  plan-core.js      модель, состояние, save/load (localStorage+EP.Cloud),
                    undo/redo (100+), проекты, версии, экспорт/импорт JSON
  plan-geometry.js  полигоны, стены из точек, точка-на-стене<->(отступ,высота),
                    пересечения стен (проходки), рулетка, сетка, привязки
  plan-canvas.js    SVG-рендер, пинч-зум/пан, слои, выделение
  plan-rooms.js     рисование комнат (полигон/прямоугольник), размеры,
                    нумерация стен, подложка + калибровка масштаба,
                    копирование/зеркалирование
  plan-elements.js  палитра, расстановка на стенах (отступ+высота),
                    пресеты высот, редактор числом, статус монтажа, фото
  plan-unfold.js    развёртка стены (плоский вид), расстановка по высоте
  plan-routes.js    щит + полу-авто ортогональные трассы, проходки, цвета
  plan-rules.js     редактируемые нормативы + живые проверки (ПУЭ/зоны/УЗО/
                    перегруз/мин.расстояния) -> предупреждения на плане
  plan-calc.js      мост в EP.PoolEngine -> материалы/смета (общая и по комнатам)
  plan-export.js    PDF (технический + клиентский), позже
  plan-mount.js     маршрут + события
pages/plan.html

=== ПОРЯДОК СБОРКИ (слоями; каждый слой — деплой и проверка вживую) ===
Слой 0 — Каркас: маршрут + пункт меню + пустой SVG-холст с пинч-зумом/паном +
         модель данных (со ВСЕМИ полями сразу) + сохранение локально/облако +
         undo/redo + список проектов. Фундамент.
Слой 1 — Комнаты: рисование полигонов/прямоугольников, размеры числом,
         нумерация стен, подложка (фото) + калибровка масштаба, слои,
         копирование/зеркало, рулетка, сетка/привязки.
Слой 2 — Элементы: палитра, расстановка на стенах (отступ+высота),
         пресеты высот (30/90/110, редактируемые), редактор, статус монтажа,
         фото к точке.
Слой 3 — Развёртка: плоский вид стены, живая связь с планом.
Слой 4 — Трассы: щит + полу-авто ортогональные трассы к нему, авто-проходки
         через стены, цвета по слою.
Слой 5 — Расчёт: мост в EP.PoolEngine -> материалы/кабель/штробы -> смета
         (общая и по комнатам); связь "план -> конфигуратор щита".
Слой 6 — Проверки норм: живые предупреждения (влажные зоны/УЗО/расстояния/
         перегруз групп).
Далее: PDF (клиентский+технический), 3D-просмотр (three.js как <script>),
       AI-проверка проекта через EP.AI, AI-автопроект по фото/плану.

=== UI ПОД ПАЛЕЦ (телефон + планшет) ===
- Добавление: тап по стене -> палитра -> элемент сел на стену.
- Точность: крупные ручки + ВВОД ЧИСЛОМ (отступ, высота) + привязка к шагу
  (напр. 10 см) и к углам/центру стены; не пиксель-в-пиксель пальцем.
- Навигация: пинч — зум, два пальца — панорама.
- Развёртка: тап по стене -> снизу выезжает плоская стена.
- Прогресс монтажа: тап по точке -> "смонтировано" ✓, видно % по объекту.

=== КАЧЕСТВО ===
Чистая архитектура, SOLID/DRY/KISS, модуль независим, расширяется без
изменения ядра. Никаких упрощений функциональности. Большой объём —
разбивать на слои (см. выше) и продолжать последовательно, единый стиль
с остальным кодом Electric Pro.
```

## ДОПУЩЕНИЯ (по умолчанию, менять по согласованию)

- Единицы — реальные см; масштаб подложки калибруется линией известной длины
  (без этого не посчитать кабель).
- Один-несколько щитов на проект; трассы идут к ближайшему.
- Несколько проектов с историей версий; хранение локально + облако.
- Комнаты — и прямоугольные, и произвольные полигоны (Г-образные и т.п.).
- Трассы рисуются с самого начала как ПОЛУ-АВТО (ортогонально к щиту,
  авто-проходки, цвет по слою); «умная» оптимизация — позже.
