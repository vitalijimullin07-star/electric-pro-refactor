```
Ты — Senior Software Architect и Full-Stack разработчик, специализация —

Добавляешь в СУЩЕСТВУЮЩЕЕ приложение Electric Pro (V29) новый режим

=== ЦЕЛЬ ===
Ощущение «прогулки по живой квартире» на мобильном телефоне/планшете:
- ходьба джойстиком, осмотр — гироскопом/акселерометром (почти VR);
- видно ВСЁ: стены/проёмы по реальной геометрии, штукатурка/материал стен,
  трассы кабеля и штробы прямо в стенах, точки (розетки/выключатели/
  светильники/щит) как 3D-объекты на своих местах;
- свет — от нарисованных на плане ламп по факту их положения, плюс
  направленное солнце в окна (по стороне света);
- КАЧЕСТВО РЕНДЕРА АДАПТИВНОЕ: сама определяет мощность устройства САМОЗАМЕРОМ
  (прогнать несколько кадров на максимум, замерить время кадра), НЕ по
  названию модели телефона — на мощном устройстве (напр. Samsung S24 Ultra)
  включает всё по максимуму (WebGPU, тени, PBR-материалы, высокое
  разрешение), на слабом — упрощает на лету.

=== СТЕК (СТРОГО как в текущем проекте) ===
- Чистый JavaScript (ES2020), без сборщика, без TypeScript, без React.
- Модули — IIFE, регистрируются в namespace EP.Plan3D.*.
- Рендер — Three.js. Подключить ЛОКАЛЬНЫМ файлом (assets/js/vendor/three/…),
  НЕ с CDN — текущий CSP (index.html, script-src) разрешает только 'self' +
  gstatic + apis.google.com, третьесторонний CDN добавлять не нужно, когда
  можно просто положить файл рядом с остальным кодом (тот же принцип, что
  и у shield-scheme-svg-v28.js — библиотека внутри проекта, без npm).
  Современный Three.js распространяется как ES-модуль — если нужны
  импорты между его файлами, использовать `<script type="importmap">` с
  локальными путями (штатная возможность браузера, сборщик не нужен).
- Состояние — то же самое project (EP.Plan.Core.project), НИКАКОГО
  дублирования модели. 3D — ЕЩЁ ОДНА ПРОЕКЦИЯ существующих данных (тот же
  принцип «одна модель — много видов», что уже используют план/развёртка/
  печатный лист).
- Только русский; строки — в одном месте (T = {...}), библиотеки строк не ставить.

=== ПРАВИЛА ПРОЕКТА ===
- Файлы не больше 300–500 строк; дробить.
- Без дублирования, костылей, магических чисел, техдолга.
- Все настраиваемые параметры (высота камеры, скорость ходьбы, пороги

- Защищённые зоны (2D-редактор плана, БД, конфигуратор щита, пул, схема)

- Офлайн-first: 3D строится из уже загруженных локальных данных, three.js

- ОБЯЗАТЕЛЬНО освобождать WebGL/WebGPU-контекст при закрытии 3D-режима

=== ТОЧКА ВХОДА ===
Кнопка в шапке редактора плана (.ep-plan-top в plan-mount.js, рядом с уже
существующей кнопкой «Во весь экран» data-plan-full) — «🚶 3D» —
открывает СВОЙ fullscreen-контейнер поверх текущего плана (НЕ тот же SVG
canvas — отдельный <canvas> для WebGL). Кнопка «✕ Выйти» возвращает в
обычный 2D-план, dispose сцены. Инициализация Three.js-сцены — ТОЛЬКО по
первому реальному входу в 3D (не при загрузке страницы) — тяжёлый код не
должен тормозить обычную работу с планом.

=== МОДЕЛЬ ДАННЫХ (читать как есть, НЕ выдумывать поля) ===
Project.settings (нужное для 3D): wallThickness (см, дефолт per-стену),
  wallMaterial, ceilingHeight, chaseW/chaseH (мм, штроба стандарт),
  tpChaseW/tpChaseH (мм, штроба тёплого пола в пол), sleeveD (мм, проходка),
  panelHeight.
НОВОЕ поле (добавить): settings.northDeg (0–360°, дефолт 0) — направление
  «север» относительно верха плана; редактируется ОДИН РАЗ стрелкой-компасом
  в настройках плана (2D, обычный UI). Нужно, чтобы солнце в окна светило с
  правильной стороны, а не произвольно.
Room { id, name, points:[{x,y}...] /*полигон, СМ*/, height /*потолок,
  null=settings.ceilingHeight*/, material /*null=settings.wallMaterial*/,
  wallTh:[см...]?, wallMat:[строка...]? /*per-стена переопределение, индекс
  = индекс ребра полигона*/, zones:["wet"?] }
  Стены — производные от рёбер комнаты: EP.Plan.Geometry.walls(room) ->
  [{id, roomId, i, a, b, len, mx, my}]; толщина/материал КОНКРЕТНОЙ стены —
  EP.Plan.Geometry.wallThOf(project, wall) / wallMatOf(project, wall).
Panel { id, x, y, name } — щит, свободная точка (не на стене).
Beam { id, a, b, width, kind:"beam"|"lintel", material } — балка/перегородка
  (kind:"lintel" — только сверху, низ свободен, проём) ИЛИ свободная
  перегородка; тоже «стена» через EP.Plan.Geometry.beamWall(beam)/wallById.
Void { id, a, b, kind:"shaft"|"room", name } — прямоугольное препятствие
  (вентшахта — непроходимый объём; "room" — только контур, без объёма).
Opening { id, kind:"door"|"sliding"|"window"|"balcony"|"opening",
  type:"door"|"window", wallId, offset, width, height, sill /*высота низа
  проёма от пола, СМ; 0 = до пола (дверные типы), >0 = окно*/, hinge, flip }

  раму+стекло, sill = высота подоконника).
Element { id, type, wallId /*null если free*/, offset, height /*СМ от
  пола, для потолочных - от пола до низа плафона*/, layer, status, params,
  circuitId, keys?, swKind?, transformer? }
  type: socket|switch|light|bra|track|ac|warmfloor|internet|tv|camera|
  sensor|output|output24|panel|junction|block(группа постов, params.items[])
  Мировая позиция маркера — EP.Plan.Geometry.elemDrawPoint(project, el).
LedStrip { id, wallId, offsetA, offsetB, height, circuitId } — сегмент
  светящейся ленты ВДОЛЬ стены (p.ledStrips).
Route { id, layer, routeType:"ceiling"|"floor", points:[{x,y}...] /*готовая
  ломаная — рисовать штробу/канал ВДОЛЬ неё как есть, ничего не
  пересчитывать*/, fromId, toId, circuitId, color, toPanel, chaseW, chaseH

Circuit { id, name, color, breaker, rcd, cable? } — линия/автомат (для

=== ЧТО ПОКАЗЫВАЕМ (пользователь явно попросил: ВСЁ) ===
1. Геометрия: стены (экструзия по толщине КОНКРЕТНОЙ стены, высота —
   room.height||settings.ceilingHeight), пол, потолок, проёмы (вырез;
   окна — рама+стекло; двери — полотно по kind, можно упрощённо), балки/
   перемычки (Beam), непроходимые объёмы вентшахт (Void kind:"shaft").
2. Электрика (слой, который включается/выключается отдельно, как «Слои»
   в 2D): точки — иконка/меш по типу (розетка/выключатель — плоская
   коробка на стене на своей высоте; светильник/бра/трек/лента — модель
   лампы со свечением; щит — шкаф); трассы — визуализировать КАК КАНАЛ
   В СТЕНЕ по факту (Route.points + chaseW×chaseH), способ — на выбор
   реализации: настоящий паз (вычесть геометрию, дороже) ИЛИ
   полупрозрачная труба/декаль на поверхности стены вдоль трассы (дешевле,
   с этого начать, апгрейд позже); проходки через стены — сквозное
   отверстие Ø sleeveD в throughWalls-точках.
3. Материалы стен: базовая — «штукатурка» (светлый шероховатый PBR-
   материал по умолчанию для всех стен, это дефолт для пользователя),
   опционально позже — процедурная текстура по wallMatOf() (Бетон/Кирпич/
   Панель/Мягкий — уже есть как enum, можно сразу задать 4 простых PBR-
   материала под них).
4. Свет: точечные/spot-источники ОТ КАЖДОГО элемента типа light/bra/track
   И от каждого ledStrip (интенсивность/цвет — дефолт тёплый белый,
   настраивается позже); ОДИН направленный источник «солнце» — направление
   вычисляется из settings.northDeg + ориентации нормали стены каждого
   окна (Opening kind:"window") — лучи идут в комнату через окно с той
   стороны, откуда реально светило бы солнце. Угол/время суток —
   фиксированный разумный дефолт («полдень»), можно дать ползунок времени
   суток позже — НЕ блокирует первую версию.

=== УПРАВЛЕНИЕ ===
- Ходьба — плавающий джойстик (появляется под пальцем в нижней трети
  экрана при касании, как стик геймпада — тянешь от центра появления,
  направление+сила = направление+скорость движения камеры). Простая
  коллизия: камера — цилиндр небольшого радиуса, не пропускать сквозь
  стены/балки/непроходимые voids (проверка по отрезкам стен, 2D в плане
  камеры, высота коллизии не нужна).
- Осмотр — DeviceOrientationEvent (гироскоп/акселерометр): наклон/поворот
  телефона поворачивает направление взгляда камеры — эффект, близкий к
  VR. НА iOS ОБЯЗАТЕЛЕН явный запрос разрешения через
  DeviceOrientationEvent.requestPermission() по прямому тапу пользователя
  (кнопка «Включить датчики» при первом входе в 3D — без явного жеста
  браузер не даст доступ). Fallback (Android без гироскопа, отказ в
  разрешении, десктоп) — осмотр свайпом пальца по экрану.
- Throttle/debounce НА ВСЕ высокочастотные события контролов — джойстик
  (pointermove), гироскоп (deviceorientation стреляет чаще, чем нужно
  кадру), resize контейнера при повороте экрана — читать последнее
  значение раз в кадр (rAF), а не обрабатывать каждое сырое событие;
  тот же принцип, что уже применён в 2D-плане (renderSceneSoon через rAF
  вместо полного рендера на каждый pointermove при drag).

=== АДАПТИВНОЕ КАЧЕСТВО (самозамер, НЕ угадывать по модели телефона) ===
Целевые устройства: 4–8 ГБ RAM, средние Android/iOS (не только топ-флагманы).
Целевой FPS: не ниже 55–60 при 100–200 электрических точках на сцене —
это ориентир для выбора уровня качества (см. ниже), не жёсткий норматив.
При входе в 3D: 1) выбрать WebGPU, если браузер поддерживает и контекст
успешно создался, иначе WebGL2; 2) прогнать несколько кадров (1–2 сек) на
максимальных настройках (тени, антиалиасинг, полное разрешение экрана,
высокое качество текстур), замерить среднее время кадра;
3) по замеру выставить уровень качества (напр. high/mid/low): high —
всё включено; mid — тени попроще/меньше разрешение теневых карт, обычный
антиалиасинг, полное разрешение рендера; low — тени выключены, рендер в
уменьшенном разрешении с апскейлом, упрощённые материалы (без PBR-бликов).
ДАЛЬШЕ — не только один замер при входе: если во время самой прогулки
FPS проседает ниже порога несколько кадров подряд — снижать качество на
уровень; если стабильно высокий запас — можно повышать обратно (гистерезис,
чтобы не дёргалось туда-сюда).
LOD (Level of Detail) геометрии — отдельно от качества рендера выше:
элементы (розетки/выключатели/светильники и т.п.) далеко от камеры
рисовать упрощённой формой (меньше полигонов, без мелких деталей меша),
детальную модель — только для точек в ближнем радиусе видимости камеры.
Актуально в первую очередь для проектов с этажами (см. p.floors —
несколько этажей в одном проекте, суммарно точек может быть заметно
больше, чем на одном этаже) — переключать LOD ПО РАССТОЯНИЮ до камеры,
не по общему числу объектов в проекте.
```

## ДОПУЩЕНИЯ (по умолчанию, менять по согласованию)

- Мебели/декора нет — только архитектура (стены/проёмы/балки/voids) и
  электрика (точки/трассы/свет). Мебель — не обсуждалась, не в скоупе.
- Компас (settings.northDeg) — новое поле, дефолт 0°; пользователь
  выставляет один раз стрелкой в 2D-настройках плана под реальную
  ориентацию квартиры.
- Время суток для солнца — фиксированный дефолт («полдень»); ползунок
  времени суток можно добавить позже, не блокирует первую версию.
- Высота камеры-игрока — рост человека (~165–175 см), без настройки в
  первой версии.
- Столкновения — упрощённая 2D-коллизия (камера как цилиндр против
  отрезков стен/балок/voids), без полноценной физики и без коллизий с
  точками/мебелью.
- Штробы в стенах — стартуем с полупрозрачной трубы/декали вдоль
  Route.points на поверхности стены (дёшево); настоящий вырез геометрии —
  возможный апгрейд позже, если производительность позволит.
- iOS обязательно требует явный тап «Включить датчики» перед тем, как
  гироскоп заработает — предусмотреть эту кнопку при первом входе в 3D.

2. Посмотри «Статус реализации» — какой слой не отмечен.
3. Скажи модели: «читай docs/3D_MODEL.md, начинай/продолжай со Слоя N».
4. Код — в `assets/js/modules/plan3d/` (новая директория) +
   `assets/js/vendor/three/`. Деплой — автоматический при мёрже в main
   (тот же пайплайн, что и у остального приложения).
